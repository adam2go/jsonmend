# The jsonmend conformance corpus

A test corpus for **JSON repair** — the task of turning the almost-JSON
that LLMs emit (truncated output, markdown fences, single quotes, bare
keys, Python literals, comments, trailing commas, …) into valid JSON.

Today every repair library invents its own semantics: the same broken
input is "fixed" differently by [json_repair] (Python) and [jsonrepair]
(TypeScript), which means a model output can parse differently on the two
sides of one system. This corpus defines repair semantics as data, so any
implementation in any language can be tested against it.

It is dedicated to the public domain (CC0, see [LICENSE](LICENSE)) —
adopt it, vendor it, send cases back.

[json_repair]: https://github.com/mangiucugna/json_repair
[jsonrepair]: https://github.com/josdejong/jsonrepair

## Format

One JSON file per case, grouped in category directories under `cases/`:

```json
{
  "input":     "{\"a\": [1, 2",
  "verdict":   "deterministic",
  "expected":  {"a": [1, 2]},
  "rationale": "close every open container",
  "source":    "jsonmend"
}
```

| field | meaning |
|---|---|
| `input` | the broken text fed to the repairer |
| `verdict` | `deterministic` \| `ambiguous` \| `unrecoverable` |
| `expected` | the single correct repair (deterministic only) |
| `accepted` | array of acceptable repairs (ambiguous only) |
| `check` | `"valid"`: only require valid-JSON output (adversarial cases) |
| `rationale` | why this is the right answer |
| `source` | provenance of the case data |

The three verdicts are the heart of the corpus:

* **deterministic** — there is one defensible repair. `{"a": [1, 2` can
  only ever mean `{"a": [1, 2]}`.
* **ambiguous** — reasonable implementations may disagree, and the
  `accepted` array enumerates the defensible answers with a rationale.
  This is exactly where today's libraries fight; writing the choices down
  is what makes the semantics a standard.
* **unrecoverable** — the input carries no JSON at all and the honest
  behavior is to raise / signal failure, not invent a value.

## Pass criteria

An implementation passes a case when:

1. its output text parses as RFC 8259 JSON (no `NaN`/`Infinity` literals
   in the output!), and
2. the parsed value equals `expected` (or any member of `accepted`).

Value equality is type-aware: numbers compare mathematically
(`1 == 1.0`), but booleans are not numbers (`true != 1`), and object key
sets must match exactly. For `unrecoverable` cases, raising an error or
returning an empty/null result both pass. For `check: "valid"` cases
only criterion 1 applies.

A reference runner lives in the jsonmend repository
([`tools/referee.py`](../tools/referee.py)); porting it is ~100 lines in
any language.

## Provenance

Case data comes from three places, tagged in `source`:

* `jsonmend` — authored for this corpus, including the programmatic
  truncation sweep (every prefix of realistic documents) and the
  degradation matrix (mechanically damaged documents whose ground truth
  is known);
* `json_repair-tests` — input/expectation pairs extracted from the test
  suite of [json_repair] (MIT, license vendored in
  [licenses/](licenses/));
* `jsonrepair-tests` — likewise from [jsonrepair] (ISC, vendored).

Cases are regenerated by [`tools/build_corpus.py`](../tools/build_corpus.py)
in the jsonmend repository; the JSON files here are the canonical
artifact.
